# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Spring Boot 4 / Java 25 backend for Guillaume's website. It is mostly an API around Île-de-France Mobilités (IDFM) public transport data: it imports the IDFM GTFS into PostgreSQL (with PostGIS, used from SQL only: no geometry is mapped by JPA) and proxies IDFM PRIM real-time and Navitia APIs.

## Commands

```bash
./mvnw spring-boot:run                 # run locally (profile "dev" is active by default)
./mvnw test                            # unit tests (*Test), a few seconds
./mvnw verify                          # unit + integration tests (*IT, Docker needed: Testcontainers), then the jar
./mvnw clean package -DskipTests       # jar only
```

Spring profiles: `dev` (default in `application.yml`, loads the gitignored `application-dev.yml` with the secrets of the development machine: local database (README), for now the same PRIM keys and JWT secret as production (local runs use the production's PRIM quotas), see `application-dev-example.yml`; SQL and file logs; dev and prod never share a database) and `prod` (document in `application.yml`: no springdoc, logs on the standard output). `application-dev.yml` is left out of the jar (`maven-jar-plugin` exclude): production reads its secrets from `/etc/guillaumedamiens/application-prod.yml` (`--spring.config.additional-location`), CI from environment variables. Virtual threads and response compression are on for both.

## Production

Debian VPS, no Docker (human procedure in `README.md`). systemd service `guillaumedamiens` (`deploy/guillaumedamiens.service`, user `guillaumedamiens`, `-Xmx2g`, `NoNewPrivileges`; the VPS is an LXC container where systemd's mount namespacing (`PrivateTmp`, `ProtectSystem`…) fails, so the unit has none) running `/opt/guillaumedamiens/current.jar`, a link into `releases/`. nginx in front: `/api/` → `127.0.0.1:8080` with per-IP `limit_req`, access log without query strings (positions), JSON 503 while restarting; personal site on `guillaumedamiens.com` (website-react, `/var/www/guillaumedamiens-site/current`, deployed by its own tag workflow), Flutter web app on `app.guillaumedamiens.com` (`/var/www/guillaumedamiens-app/current`), administration (website-admin, static, CSP) on `admin.guillaumedamiens.com` (`/var/www/guillaumedamiens-admin/current`); files in `deploy/nginx/`, applied by `deploy/nginx/apply.sh`; the static sites also log their page loads to `/var/log/guillaumedamiens/pages.log` (directory `root:guillaumedamiens` 0750, rotated by `deploy/logrotate/guillaumedamiens-pages`) for the visit counts. Deployment: tag `vX.Y.Z` (the release: refused otherwise, written in the jar's build-info) → `.github/workflows/deploy.yml` publishes the jar in the tag's GitHub release, then the VPS downloads it as the `deploy` user (uploads from GitHub's runners to the VPS crawl at ~20 KB/s; checked against its SHA-256) (allowed to `systemctl restart guillaumedamiens` only) and runs `deploy/activate-release.sh` (switch, restart, wait for `GET /api/health`, roll back otherwise, keep 5 releases). `.github/workflows/build.yml` builds on each push and starts the jar against an empty PostGIS 18 (Liquibase + Hibernate validation): a new required extension must be created there too. `deploy/migrate-server.sh` did the one-time move from the former root service.

## Architecture

Package root: `com.gdamiens.website`.

- **Security** (`security/WebSecurityConfig`): stateless JWT via Spring's OAuth2 resource server (HS256, Nimbus encoder/decoder). Authorities come from the `auth` claim with no prefix: `ROLE_ADMIN` or `ROLE_USER` (stored in `user.role`, a new Google account gets `ROLE_USER`; admin-only endpoints use `@PreAuthorize("hasRole('ADMIN')")`), or `ROLE_GUEST` for a device used without account (`Role.isGuest`). Open paths: `/api/auth/google`, `/api/auth/guest`, `/api/auth/api-token`, `/api/token/refresh`, `/api/logout`, `/api/health`, `/error` and Swagger/api-docs (dev only); `/api/v2/me/**` needs `ROLE_USER` or `ROLE_ADMIN`, the rest of the API any token. Guest tokens (`POST /api/auth/guest`, `UserService.createGuestToken`): JWT signed like the others, subject `guest:<uuid>`, 30 days, no refresh token, never stored; at most `application.budget.guest-tokens-per-ip-per-hour` per IP. Sign-in with Google (`POST /api/auth/google { idToken }`, `GoogleIdTokenVerifier`: RS256 signature against Google's JWKS (`application.google.jwk-set-uri`, cached by Nimbus), issuer `accounts.google.com`, audience in `application.google.client-ids` (empty = 503, disabled), expiry, `email_verified`; no Google secret, no Google token kept): the account is found by `user.google_sub` or created with the login `google:<sub>` (also its JWT subject, so the rest of the code is unchanged), its email (unless another account already holds it: never merged) and first name (`display_name`) follow Google's, `last_login_at`; an email in `application.admin-emails` gets `ROLE_ADMIN`. Sign-in is Google only: password accounts and endpoints are gone (changeset `011`). Personal API tokens for Bruno and scripts (`ApiTokenService`, `ApiTokenController` `/api/v2/me/api-tokens`, admins only, at most 10, 365 days): opaque `gdpat_…` values (`utils/OpaqueTokens`, SHA-256 stored in `public.api_token`, JDBC) exchanged at `POST /api/auth/api-token` for a 1 h access JWT without refresh token. `AccountController` (`/api/v2/me`: account, `/export` GDPR JSON with the favorites, `DELETE` for good, cascading favorites and refresh tokens). Google sign-in returns a 1 h access JWT plus an opaque refresh token (`RefreshTokenService`: SHA-256 hash stored in `public.refresh_token`, rotated on each use, reuse revokes all the user's tokens). CORS origins come from `application.cors-allowed-origins` (`application.yml`: the production web app `app.guillaumedamiens.com` and the administration `admin.guillaumedamiens.com`; the `dev` profile document replaces them with `localhost:[*]` and `127.0.0.1:[*]`, for the dev apps). `RateLimitFilter` (Bucket4j, in-memory buckets in `RateLimiter`, added after the bearer filter) limits `/api/**` per minute: per IP on auth endpoints, per account or guest device when authenticated, per IP otherwise (`application.rate-limit.*`); 429 + `Retry-After`. `UsageBudgets` (on `RateLimiter`, longer buckets) caps the journey searches: per guest device and day, per account and day/hour (`application.budget.*`); 429 with problem detail `code` `journey_limit` (`guest_journey_limit` for a guest: signing in helps). Problem details may carry a stable `code` (`CustomException.getCode()`) the apps act on. Client IPs come from `X-Forwarded-For` via `server.forward-headers-strategy: native`
- **Controllers** (`controller/`): all under `/api`. `UserController` (sign-in/up, token refresh, logout), `HealthController` (`GET /api/health`: 200 when the database answers, with the release running: `AppVersion`, the tag's `X.Y.Z` given by the deploy workflow as `-Dapp.version` to `build-info`, `dev` otherwise), `GtfsController` (GTFS import, admin), `AdminController` (`GET /api/admin/status`, admin: PRIM quotas used today with the guests' share and PRIM's own count, calls per feature, circuit breakers, last GTFS imports and `gtfsStale` after 26 h without success, traffic snapshot time: what supervision watches; `POST /api/admin/actions/*`: traffic or elevators fetched now, stop search index rebuilt, PRIM circuits closed, obsolete sessions deleted), `AdminStatsController` (`GET /api/admin/stats/*`, admins, for website-admin: `AdminStatsService` + `AdminStatsRepository`, JDBC aggregates only, never an account's id, email, name or a position: accounts (active per day from the refresh tokens, rotated every hour of use and kept 7 days), favorites (most saved stop areas and lines), PRIM calls per day from `api_quota_usage`, GTFS and database sizes, JVM and machine, and the pages of `application.monitored-sites` checked at most once a minute: status, time, TLS certificate expiry; `/usage` and `/audience` from `usage/`, below) and the mobility API in `controller/v2/`.
- **Usage statistics** (`usage/`, anonymous, for website-admin): `UsageFilter` (in the security chain after the JWT authentication and before `RateLimitFilter`, so its 429 are counted) gives `UsageRecorder` each `/api/**` request: route as matched by Spring (ids replaced otherwise), kind of caller (ACCOUNT, GUEST, ANONYMOUS), status class, time; and the day's distinct members: `active:account`, `active:guest`, `platform:<X-App-Platform>`, `version:<X-App-Version>` (headers sent by the app). Counts are kept in memory and added to `usage_hourly` every minute and at shutdown; members are keyed hashes (HMAC, 8 bytes) with the day's random salt (`usage_salt`) in `usage_member`, turned into `usage_daily` counts each night at 0:10 (and at startup), then deleted with the salt: a past day's count can't be linked to anyone. `PageViewReader` reads every 5 minutes the page loads of the static sites that nginx writes to `application.pages-log` (`/var/log/guillaumedamiens/pages.log`, format `guillaumedamiens_pages`: the requested path without its query string, snippet `deploy/nginx/guillaumedamiens-pages-log.conf`, kept 3 days by `deploy/logrotate/guillaumedamiens-pages`): from where it stopped (`usage_log_cursor`: inode and position, the `.1` file's end first after a rotation), pages only (no assets, no robots, GET 200/304): views per page (`usage_page_daily`), visitors per site (IP + browser as a member `visitors:<host>`), referring sites (host only, `usage_referrer_daily`). No account id, IP, browser or position is stored.
- **External clients** (`client/`): PRIM clients extend `PrimClient` (API key header in `request()`, and `call(feature, request)` around every PRIM request: `PrimCircuitBreaker` refuses it at once while that API is considered down, else it is counted by `ApiQuota` and its outcome reported; no answer, a 5xx or a 429 become `PrimUnavailableException`, 503 `prim_unavailable`, which callers handle like any real-time failure. The breaker opens after 5 failures in a row, for 30 s (5 min after a 429), then lets one call try again): `PrimRealtimeClient` (PRIM stop-monitoring as `StopCall` records, estimated-timetable as SIRI Lite DTOs of `client/siri/`, read by `SIRI_JSON`: text tags such as `DestinationName` as a list of one object or, since IDFM's new real-time platform (end of October 2026, `SiriJson.newPlatform` in the tests), as the object alone; unknown tags like `RecordedCalls` ignored), `NavitiaClient` (journeys, places, walking paths; raw `JsonNode`), `DisruptionsClient` (PRIM `disruptions_bulk`, raw `JsonNode`). `GtfsDatasetClient` reads the GTFS dataset on Opendatasoft (version, file link, download; not PRIM, no quota), `StopZoneClient` the towns of the stop areas, `ElevatorClient` the elevators, `GeoplateformeClient` the IGN geocoder. External calls use `RestTemplate` on one shared Apache HttpClient 5 pool (`configuration/HttpClientConfig`: 3 s connect, 10 s read timeout or 60 s for bulk downloads, 50 connections per host, no automatic retry); their base URLs are `application.urls.*` (`prim`, `gtfs-dataset`, `velib-gbfs`, defaults in `ApplicationProperties.Urls`). `ApiQuota` and `PrimCircuitBreaker` read the time from the `Clock` bean (`ClockConfig`).
- **Services** (`service/`): the mobility logic below, on the clients and `NetworkRepository`. Times of the network go through `utils/ParisTime` (Europe/Paris, GTFS service-day times, Navitia local times), distances through `utils/Geo`.
- **Database schema**: owned by Liquibase (`resources/db/changelog/db.changelog-master.yaml`, formatted SQL changesets in `changes/`). Hibernate runs with `ddl-auto: validate` on the `public` entities (`user`, `refresh_token`, `favorite`; `gtfs_import`, `api_token`, `api_quota_usage` and the `usage_*` tables are read with JDBC): a change there needs a new changeset and matching entity types (e.g. `smallint` ↔ `Short`). Everything else lives in the `gtfs` schema, read with native SQL only (no JPA entity).
- **GTFS import**: `service/GtfsImportService` downloads the IDFM GTFS zip and streams each file into PostgreSQL with `COPY` (pgJDBC `CopyManager`), no Java row parsing. Each import clones the Liquibase-defined `gtfs` tables into `gtfs_new` (`LIKE`, without keys/indexes), loads them, runs `resources/gtfs/post_load.sql` (builds `shapes` LineStrings and the derived `route_stops`), copies keys and indexes from `gtfs`, then swaps `gtfs_new` → `gtfs` in the same transaction (failure = rollback, old data kept). Tables and columns use GTFS names (`gtfs.stops.stop_id`…); unknown header columns make the import fail until a changeset adds them. Triggered by `batch/GtfsUpdateWatcher` (every 15 min, imports when the Opendatasoft dataset's `data_processed` date, public metadata, is newer than the last successful import's: IDFM publishes at 8 h, 13 h on working days and 17 h on disruption days; a failed version is retried after 2 h) or `POST /api/gtfs` (async, 409 if running). Each import is recorded in `public.gtfs_import` (JDBC only, `GtfsImportRepository`: source, version, status, rows per table or error; `GET /api/gtfs/imports` for admins; imports left running are closed at startup); it refuses to start under `application.gtfs.min-free-disk-gb` free (temporary directory's disk, the new schema sits next to the current one). A successful import publishes `GtfsImportedEvent`: services caching GTFS data (`NetworkService`, `TimetableService`, `JourneyService` shapes) drop their caches, so add a listener to any new long-lived GTFS cache.
- **Lines**: API line ids are IDFM ids (`C01371`), GTFS route ids are `IDFM:C01371` (`IDFMRoute.toRouteId/toLineId`). `TransportMode.fromGtfs()` maps `route_type` + agency (RER/TER/Transilien) + `N…` short names (Noctilien).
- **Mobility API v2** (`controller/v2/MobilityController`, `/api/v2/...`, DTO records in `controller/object/v2`): endpoints for the apps (nearby, stop area, departures, line, search). A stop area is a GTFS parent station (`location_type = 1`, `IDFM:71264`, every quay has one); it is also the SIRI stop-monitoring `MonitoringRef` (`STIF:StopArea:SP:71264:`) and the Navitia `stop_area:IDFM:71264`. GTFS reads go through `NetworkRepository` (`NamedParameterJdbcTemplate`, native SQL). `DepartureService` merges PRIM real time with GTFS scheduled departures for lines without real time, cached 30 s per stop area (`utils/TtlCache`, no cache library). A stop area can hold two consecutive stops of a line under different names (Gare Saint-Lazare: "Gare Saint-Lazare" and "Pasquier - Anjou" for the bus 22), each bus then coming twice: `withoutNeighbourStopRepeats` leaves out the stop whose passages mostly come 0 to 5 min after the other's (same line and destination; `StopCall.stopName` from `StopPointName`; platforms of the same name and different train numbers never compared). `NetworkService.getLineDetail` groups trips by stop pattern, re-orients them (GTFS `direction_id` is unreliable, e.g. RER A) and merges express/short-turn patterns into branches. `SearchService` (`/search`, `/places/reverse`): Navitia only as a last resort. Lines matched by name; stop areas from `StopSearch` (every served GTFS stop area in memory with its town from the IDFM stop zones open data, `StopZoneClient`, `zdcid` = stop area; words in any order and unfinished, accents, `st`/`saint`, a typo per word; ranked by match, heavy modes, lines, closeness; built in the background at startup and after each GTFS import); addresses and places from the IGN Géoplateforme (`GeoplateformeClient`, no key, 50 requests/s per IP: one `index=address,poi` call per text, cached 10 min per text and ~1 km area; Île-de-France postcodes only, stations left out); Navitia `places` when the Géoplateforme fails or nothing was found. `/places/reverse`: the position named after its closest address within 250 m (Géoplateforme, cached 1 h). `JourneyService` (`/api/v2/journeys`): Navitia journeys read as raw `JsonNode` (snake_case, only the needed fields) and mapped to options/sections with GTFS lines and stop areas; modes filter = forbidden Navitia physical modes; `earlier`/`later` cursors from Navitia's prev/next links. The same search within a minute (positions on a 0.0005° grid, ~50 m, sent to Navitia as such; time to the minute; same options) is answered from a 60 s cache; GTFS shapes are added after it. Navitia has no path for some trips (e.g. Transilien L direct trains: straight segments between stops); such rides (about one point per served stop) get the GTFS shape of their line cut between the two stops (`NetworkRepository.findShapeBetween`, PostGIS `ST_LineSubstring`), looked up in parallel within a 300 ms budget and cached 6 h. `FavoriteController` (`/api/v2/me/favorites`, user from the JWT subject): `public.favorite` rows (HOME/WORK one each, PLACE, STOP by stop area id, LINE by line id; partial unique indexes), returned with current GTFS stop/line data. `TrafficService` (`/traffic`, `/lines/{id}/disruptions`, `/stops/{id}/disruptions`): one PRIM `disruptions_bulk` call (its own quota, 0.2 s, 1.4 MB; no conditional requests) gives every disruption with the objects it impacts per line: the line or its network (→ `lineIds`), stop points (quays → their stop area, stop-only), and sometimes `impactedSections` (→ `sections`, named as in the GTFS); active / upcoming (7 days) from the application periods; the snapshot is shared, refreshed in the background when a request finds it older than 3 min (nothing fetched while nobody asks; stale served meanwhile and kept on failure). Elevator outages come from the open data "État des ascenseurs" (`ElevatorClient`, Opendatasoft with the static key, not PRIM; `zdcid` = GTFS stop area), same refresh every hour, the stops answering without them while it is down (tried again after 5 min). Web messages are HTML turned into plain text. `VehicleService` (`/lines/{id}/vehicles`, cached 60 s: estimated-timetable quota): PRIM estimated-timetable of the line, calls at quays `IDFM:<id>` (or `IDFM:monomodalStopPlace:<id>` for RER) mapped to stop areas. Real vehicle journeys (SNCF, Métro 14) are matched against the line's branches (branch serving the next stop then most following calls in order). Most RATP lines and buses only give the next passages per stop under made-up journeys mixing vehicles (detected when > 20 % of journeys don't follow a branch): vehicles are then followed stop by stop along each branch (a passage continues the earliest vehicle seen at one of the two previous stops that can get there by then, since stops sometimes miss a vehicle; otherwise it is a vehicle that has left the previous stop; direction from the journey's destination). Progress between the stop left and the next one from the expected times. Each vehicle comes with its next calls (times, delay, platform) and, for SNCF, its mission code (`VehicleJourneyName`). `RideService` (`/lines/{id}/rides?from=&to=&after=`, cached 30 s per minute of `after`): the stop's departures of the line that stop at `to`, then the GTFS trips from `from` to `to` beyond what the stop lists (real time only goes so far), from `after` (a connection) on, with their arrival there from the stop-monitoring of `to` (`DepartureService.getArrivals`, shared 30 s cache of the raw calls: same train number, else the vehicle towards the same destination expected about when it should arrive; no estimated-timetable, its quota is small), else the GTFS trip (same train number = `trips.trip_short_name`, whose `trip_headsign` is the SNCF mission code) shifted by its delay, else the line's usual ride time (`typical`); numbered trains missing from the schedule between `from` and `to` are left out. `Departure.mission` / `trainNumber` come from stop-monitoring `VehicleJourneyName` / `JourneyNote`. `TimetableService` (`/stops/{id}/timetable?lineId=&date=`, cached 6 h): GTFS departures of a line over a service day, grouped by direction of the line detail (GTFS `direction_id` as fallback), same train under several calendars counted once. `BikeService` (`/bikes/stations`, `/bikes/nearby`): Vélib GBFS open data (station information every 6 h, status every minute, last data kept on failure). `journeys?bikeShare=true` adds a `bike_share` option built in `JourneyService` (closest station with a bike / with a dock within 600 m; walks to and from them estimated from the distance; the ride is Navitia's walking path between the stations, cached 24 h per pair, at 15 km/h: PRIM has no bike routing nor Vélib stations). PRIM's Navitia quota is small: no isochrones / heat maps, and new Navitia calls must be cached. Errors as `ProblemDetail` (`MobilityExceptionHandler`)
- **External API DTOs**: `client/siri/` holds the SIRI Lite types of stop-monitoring and estimated-timetable (`client/StopCall` flattens a stop visit); Navitia responses are read as `JsonNode` (`service/NavitiaJourneys` maps journeys).
- **Errors**: `controller/ApiExceptionHandler` answers every controller's errors as problem details (`CustomException` with its `code`, 400 for bad parameters or body, 403 for `@PreAuthorize` refusals, 500 otherwise).

## PRIM quotas (per day, marketplace account) — design with them

Every external call must fit these; cache server-side and share one fetch between users. `client/ApiQuota` counts the calls made through `PrimClient.call(feature, request)` under their `ApiQuota.Feature` (departures, vehicles, journeys, walking paths, places, traffic: each belongs to one API) and refuses above 90 % of the daily quota (callers fall back: no vehicles, schedule only…). Guest devices only get `application.quota.guest-share` (15 %) of each quota, at most 1/16 of it per hour, so the accounts always keep 75 %: the caller is read from the `SecurityContext`, so worker threads must get it (`DelegatingSecurityContextExecutorService`, as in `DepartureService` and `JourneyService`); background tasks count as accounts. The count catches up with PRIM's (`x-ratelimit-limit-day` / `x-ratelimit-remaining-day` headers of each answer: the development machine shares the keys) and survives restarts: `ApiQuotaStore` saves the day's counts per feature in `public.api_quota_usage` every 30 s and at shutdown, and reads them back at startup. Refusals are `QuotaExceededException` (503, `code` `quota_exhausted` / `guest_quota_exhausted`): a refusal of the guests' share must not be cached in a shared cache (departures and vehicles rethrow it out of the `TtlCache` loader and fall back for that caller only).

## Tests

Run in CI on every pull request and push to master (`.github/workflows/build.yml`, check "Build and test", required to merge), after which the production jar is started against an empty PostGIS.
- Unit tests (`src/test/java`, `*Test`): JUnit 6, AssertJ, Mockito (loaded as an agent by surefire/failsafe). Pure logic is tested directly: quotas (`MutableClock`), circuit breaker, caches, budgets, Navitia and SIRI parsing (`src/test/resources/navitia/*.json`), line branches, text cleanup.
- Integration tests (`it/`, `*IT`, failsafe): `support/IntegrationTest` starts the whole application on a random port against a throwaway PostGIS (Testcontainers, `postgis/postgis:18-3.6` like the CI; one container and one application for all the test classes) with the `test` profile (`src/test/resources/application-test.yml`: scheduling off, test JWT secret, Google client and admin email of the tests). The external APIs are a local `FakeServer` (JDK HttpServer) whose default answers (`ExternalApis`) match `MiniGtfs`, a small network (métro 1, RER A with two branches, bus 38, Noctilien N11) imported through the real GTFS import before the first test. Google ID tokens are signed by a key of the tests (`GoogleTokens`). Tests call the API over HTTP (`Api`: each instance is a client at its own IP through `X-Forwarded-For`), and keep apart what the application keeps in memory (users, IPs, stop areas: rate limits and caches are shared); `@AfterEach` closes the circuit breakers.
- Locally, Docker must be usable by the user (group `docker`).

## Gotchas
- Stop ids : StopArea vs StopPoint vs monomodalStopPlace
- GTFS is theoretical while SIRI is realtime

## Other

- `Bruno/` is a Bruno (OpenCollection YAML) collection covering every `/api` endpoint: `Auth`, `Admin`, `Mobility (v2)` (`Auth / Guest token` stores a guest JWT in `guestJwt`). Auth is collection-level (bearer `{{jwt}}` + a before-request script in `opencollection.yml` that exchanges the environment's `apiToken` at `/api/auth/api-token` when the JWT is missing or expiring). Example ids are collection variables. Add a request for each new endpoint.
